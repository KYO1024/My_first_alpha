# 主题强趋势股二波/修复行情交易法

## 策略定位

本策略只处理一种结构：主题仍在市场主线内，个股已经完成一波强趋势，随后进入分歧/缩量修复，并等待二波触发。

它不是全市场选股器，也不是自动交易系统。它的目标是把候选池里的股票分层，回答三个问题：

- 哪些还在一波强势中，适合继续观察？
- 哪些进入分歧修复，已经值得重点盯盘？
- 哪些已经接近二波触发价，需要准备执行计划？

## 研究闭环

借鉴 Vibe-Trading 的轻量研究工作流，本项目保留三类可追溯信息：

- **Strategy Playbook**：本文档，固定交易法定义、买点、卖点和失效条件。
- **Hypothesis Registry**：`config/hypotheses.json`，记录主题假设、触发条件和复盘提示。
- **Run Card**：每次扫描自动生成 `reports/latest_run_card.json`，记录候选池版本、数据源、参数、阶段分布和重点跟踪名单。
- **Decision Log**：每次扫描自动更新 `reports/decision_log.jsonl` 和 `reports/decision_log.md`，记录重点信号的看多理由、看空风险、风险审查、执行条件，以及后续 1/3/5/10 日表现。

## 阶段定义

| 阶段 | 含义 | 处理动作 |
|---|---|---|
| 二波确认 | 已放量站回短均线或突破修复平台 | 按触发价和失效价执行 |
| 分歧修复 | 一波后缩量回撤，结构仍未破坏 | 重点跟踪，等待触发 |
| 一波强势 | 主升仍在延续，分歧尚不充分 | 观察是否进入修复 |
| 弱观察 | 结构或强度不足，但未明确失败 | 降低优先级 |
| 结构失败 | 跌破关键均线或放量破位 | 剔除或降级 |
| 数据不足 | 行情源或历史数据不足 | 不做判断 |

## 核心条件

### 候选池

候选池来自 `watch_list.xlsx`，至少包含股票代码。推荐同时维护：

- 股票名称
- 主题/题材
- 行业/板块
- 主题强度
- 备注

候选池是人工主观判断入口，扫描器只负责把候选股按结构客观分层。

### 一波强度

优先选择近期已经打开空间的标的：

- 近期高点相对前期低点涨幅充足
- 价格仍接近一波高点区
- 主题或板块仍有资金记忆

### 修复质量

理想修复不是大跌，而是健康分歧：

- 高点后修复天数适中
- 回撤幅度不过深
- 修复期缩量
- 尽量守住 MA10/MA20

### 二波触发

触发不是“看好”，而是结构再次转强：

- 重新站上 MA5/MA10
- 接近或突破修复平台高点
- 放量确认
- 距触发价收敛，优先关注 0-5% 区间

### 失效条件

以下情况需要剔除或降级：

- 跌破 MA20/MA60 后无法收复
- 高位放量下跌
- 回撤过深，二波结构被破坏
- 主题退潮或核心标的转弱
- 行情数据过旧或数据源异常

## 执行看板

Discord 推送优先展示：

- 重点跟踪：分歧修复、二波确认、一波强势中最接近触发的标的
- 距触发：当前价到触发价的距离
- 数据日：最新行情日期
- 数据源：`akshare`、`yfinance` 或 `local_csv`
- 执行条件：触发价、失效价、当前阶段下是否可执行

本地 Markdown/CSV 报告保留完整字段，用于复盘。

## 多空与风险审查

项目吸收 TradingAgents 的研究结构，但不用 LLM 多 Agent，而是用规则化文本输出三类视角：

- **看多理由**：来自评分规则中的支持理由，例如主题标注、缩量修复、站上均线、放量确认。
- **看空风险**：来自风险规则中的扣分项，例如回撤不充分、跌破均线、放量下跌、修复时间过长。
- **风险审查**：按阶段给出执行提醒，例如一波强势不追高、修复阶段不提前重仓、确认阶段必须带失效价。

这三类视角不会改变分数，但会帮助复盘“为什么当时可以看、为什么不能买、错在哪里”。

## 复盘规则

每次实际交易或观察后，建议回看对应 run card：

- 扫描时属于哪个阶段？
- 距触发价是多少？
- 数据源是否可靠，行情日期是否新鲜？
- 是否严格遵守失效价？
- 主题假设是否仍成立？
- 信号后 1/3/5/10 日收益是否符合预期？
- 是否触发买点，还是先跌破失效价？

复盘结论再反向更新 `config/hypotheses.json` 和本策略文档。
